# Product Requirements Document (PRD)
## The Lenny Growth Assistant

---

## 1. Forward Deployment Discovery Brief

### 1.1 User and Problem Statement
- **Target User**: Product Managers, Growth Leads, Founders, and Forward-Deployed Engineers.
- **Job to Be Done**: Extract actionable growth frameworks, product strategy takeaways, and publishable content from Lenny's Podcast and Newsletter corpus without manually sifting through hundreds of audio transcripts or writing complex prompts.
- **Pain Point**: Product teams struggle to convert raw transcript conversations into grounded decision frameworks, structured essay drafts (e.g. Ship 30 for 30 methodology), and interactive HTML dashboards. Existing generic chatbots hallucinate metrics and lack verifiable source citations.

### 1.2 Success Metrics
- **Grounding Citation Accuracy**: 100% of generated responses must cite at least 1 verified podcast/newsletter source from the knowledge base.
- **Content Output Quality**: "Ship 30 for 30" skill generates ~1,250-word structured essays featuring a compelling hook, skimmable headings, bulleted takeaways, and direct guest quotes.
- **Artifact Security Isolation**: 100% of HTML artifacts render natively inside a sandboxed iframe (`sandbox="allow-scripts"`) preventing cross-origin data leakage.
- **Evaluator Time-to-Value**: evaluator can start the full stack with 1 command (`python run.py` or `docker-compose up`) and run local Ollama or Fallback models in under 60 seconds.

### 1.3 Key Assumptions
1. Transcripts are formatted in Markdown with structured frontmatter metadata (title, guest, date, post_url).
2. The evaluator machine may or may not have cloud API keys (Anthropic/OpenAI) or a running Ollama daemon. A resilience fallback engine must maintain 100% system uptime under all connectivity conditions.
3. Interactive HTML artifacts generated by LLMs are treated as untrusted user-generated code requiring iframe sandboxing.

### 1.4 Scope Choices
- **Included**:
  - Full-stack web application (FastAPI backend + React Vite frontend).
  - Hybrid RAG search engine combining sparse BM25 and TF-IDF vector embeddings.
  - Flexible LLM layer supporting Ollama (Local), Anthropic Claude 3.5 Sonnet, OpenAI GPT-4o, and Fallback Mock.
  - Interactive side-by-side Sandboxed Artifact Viewer for live HTML and Markdown preview.
  - Specialized "Ship 30 for 30" 1,250-word essay generation skill tool.
  - Dual database persistence (SQLite for zero-config local, PostgreSQL for Docker Compose).
- **Excluded**:
  - User multi-tenant authentication (out of scope for single-team internal growth assistant).

### 1.5 Risk Matrix & Mitigation Strategy

| Risk | Impact | Likelihood | Mitigation Strategy |
| :--- | :--- | :--- | :--- |
| **Model Hallucination** | High | Medium | Strict system prompts instructing agent to rely strictly on retrieved RAG transcript chunks and provide explicit citation accordions. |
| **Ollama/API Outages** | High | Low | ProviderRegistry with auto-resilience fallback engine that catches API errors and gracefully serves grounded fallback answers. |
| **XSS / Malicious HTML Execution** | Critical | Low | Artifact Viewer renders HTML inside `iframe` with `sandbox="allow-scripts"` and clean origin isolation. |
| **Ingestion Latency** | Medium | Medium | Pre-chunked and indexed TF-IDF vector store loaded into memory on startup. |

## 2. Product Requirements & User Flows

### 2.1 User Flow 1: Grounded Q&A Consultation
1. User enters a product management question in the chat input.
2. Agent runs hybrid search against Lenny's transcript corpus.
3. Response streams back formatted with markdown headings, key bullet points, and a collapsible "Grounded Sources" drawer displaying guest name, episode title, and excerpt.

### 2.2 User Flow 2: Ship 30 for 30 Essay Generation
1. User clicks the "Ship 30 Masterclass Essay" preset button or types "Write a 1,250-word Ship 30 essay on PLG".
2. Agent routes query to `Ship30For30Skill`.
3. System produces a ~1,250-word essay structured into:
   - The Hook
   - Narrative & Deep Insights
   - Actionable 4-Pillar Framework
   - 5-Step Tactical Playbook Checklist
   - Grounded Transcript Citations

### 2.3 User Flow 3: Interactive Artifact Rendering
1. User requests an interactive component (e.g. "Generate an HTML Growth Metrics Calculator").
2. Agent generates complete HTML/CSS snippet.
3. Frontend automatically triggers the side-by-side Artifact Viewer, rendering the live calculator inside an iframe sandbox alongside code copy/download controls.

## 3. Acceptance Criteria
- [x] Backend built with FastAPI and SQLite/PostgreSQL persistence.
- [x] RAG ingestion engine parses transcript frontmatter and chunks text into semantic segments.
- [x] Dynamic LLM switcher supports Ollama local model, Anthropic Claude, OpenAI, and Fallback engine.
- [x] Ship 30 for 30 skill enforces ~1,250-word structure with skimmable typography and takeaways.
- [x] Artifact viewer renders HTML in isolated iframe sandbox.
- [x] Single-command execution (`python run.py`) starts the backend and frontend seamlessly.
